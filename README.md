# ZOTA Net для Home Assistant — 0.1.1

Интеграция только для чтения котлов **ZOTA Solid X** через облачный API ZOTA Net. Основана на анализе Android-приложения 2.11.3 и реальном диагностическом ответе Solid X. Минимальная версия Home Assistant: **2024.12**. Это предварительная версия; требуется проверить работу на вашей установленной версии HA и аккаунте.

## Изменения 0.1.1: jitter между повторными попытками

Каждая пауза между повторами текущего запроса случайно выбирается из диапазона **80–120%** настроенной задержки. Например, базовая задержка 5 секунд даёт фактическую паузу 4–6 секунд; значение по умолчанию 2 секунды — 1,6–2,4 секунды. Новое значение выбирается независимо перед каждой повторной попыткой.

Настройка задержки — базовая величина. Число повторов, рост таймаута и список повторяемых ошибок сохраняются. При 0 повторах пауз нет. В debug-журнал выводится фактическая выбранная пауза с точностью до сотых секунды.

Обновление доступно через HACS как версия 0.1.1; после установки перезапустите HA. Перенастройка интеграции не требуется.

## Изменения rc4: увеличение таймаута при повторах

Чтение текущих показаний начинается с таймаута **20 секунд**. Каждая дополнительная попытка получает ещё 20 секунд: **20 → 40 → 60 → 80 → 100 → 120**. Максимум определяется числом повторов (0–5) в настройках; при 3 повторах это 4 попытки с таймаутами 20, 40, 60, 80 секунд.

В начале следующего цикла опроса таймаут снова равен 20 секундам. Авторизация, список котлов и история сохраняют прежний таймаут 20 секунд. Повторная авторизация внутри одной попытки current не сбрасывает её таймаут. Между попытками действует выбранная пользователем задержка.

Сообщение о локальном таймауте теперь содержит лимит именно этой попытки. Серверный HTTP 504 отличается от локального таймаута: он может прийти раньше выбранного лимита, и увеличение времени ожидания клиента не изменяет таймаут шлюза ZOTA.

Длительность цикла может увеличиться. При 3 повторах и задержке 5 секунд четыре запроса current могут занять до 218 секунд с учётом jitter, без учёта возможных запросов авторизации и истории. Новый цикл не начинается параллельно предыдущему.

Обновление с rc3: замените `api.py` и `manifest.json` в `/config/custom_components/zota_net`, затем перезапустите HA. При обновлении с более ранней версии замените всю папку интеграции.

## Изменения rc3: настройка повторов

В **Настройки → Устройства и службы → ZOTA Net → Настроить** добавлены:

- **Повторные попытки после ошибки:** 0–5, по умолчанию 1. Это число дополнительных попыток после первого запроса; 0 отключает их.
- **Задержка между попытками:** 1–60 секунд, по умолчанию 2.

Настройки применяются ко всем выбранным котлам этой записи интеграции. После сохранения HA перезагружает запись автоматически. Старые записи без новых параметров используют 1 повтор через 2 секунды; миграция и повторный ввод данных входа не нужны.

Механизм относится к чтению **текущих показаний**, с прежним перечнем временных ошибок: таймаут, соединение/DNS, неполный ответ, HTTP 5xx. История сохраняет прежнее поведение. Ошибки авторизации обрабатываются отдельно: при 401/403 выполняется прежняя однократная повторная авторизация, даже если retry_count=0.

При нескольких ошибках цикл опроса занимает время всех попыток и задержек. Например, 3 повтора означают до 4 запросов текущих показаний. Пока они не завершатся, следующий цикл не выполняется параллельно. После исчерпания попыток сенсоры становятся unavailable; сохранённое значение не выдаётся за свежий замер.

Обновление: замените всю папку `/config/custom_components/zota_net` папкой из архива rc3, затем перезапустите HA. Интеграцию удалять не требуется.

## Изменения rc2 и обновление с rc1

В rc1 один неудачный запрос current сразу делал все сенсоры котла unavailable, а причина API терялась в общем сообщении `No current readings available from ZOTA`.

В rc2 после таймаута, ошибки соединения/DNS, неполного ответа или HTTP 5xx выполняется одна дополнительная попытка чтения текущих показаний через 2 секунды. Таймаут каждой попытки — 20 секунд. Ошибки сертификата TLS, структуры/JSON и другие HTTP-коды этим механизмом не повторяются. Для 401/403 действует отдельная прежняя логика однократной повторной авторизации.

Если обе попытки неудачны, сенсоры становятся unavailable; последнее значение не выдаётся за новое измерение. Журнал HA теперь содержит безопасную причину: например `boiler 1: ZOTA returned HTTP 503`, `Request timed out (20 seconds)` или `Connection or DNS error`. Номер котла соответствует порядку выбранных устройств; пароль, токен, серийный номер и тело ответа не включаются.

Чтобы обновиться, замените папку `/config/custom_components/zota_net` папкой из нового архива и перезапустите HA. Удалять интеграцию и вводить логин заново не требуется; настройки и идентификаторы сенсоров сохраняются.

Причина сбоев конкретного сервера/соединения по старому общему журналу не установлена. Повторная попытка уменьшает последствия кратких сбоев; постоянную проблему соединения или API она не устраняет.

## Установка из архива

1. Распакуйте архив.
2. Скопируйте папку `custom_components/zota_net` в каталог конфигурации Home Assistant: `/config/custom_components/zota_net`.
3. Перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → ZOTA Net**.
5. Введите логин и пароль ZOTA и выберите котлы Solid X.

Пример конечного расположения: `/config/custom_components/zota_net/manifest.json`. Не копируйте весь архив в custom_components дополнительным вложенным каталогом.

## Установка и обновление через HACS

Репозиторий: **https://github.com/tsrman/zota-net-ha**.

1. Откройте **HACS → ⋮ → Пользовательские репозитории (Custom repositories)**.
2. Добавьте `https://github.com/tsrman/zota-net-ha`, тип **Integration**.
3. Найдите **ZOTA Net** и скачайте интеграцию.
4. Перезапустите Home Assistant.
5. Добавьте ZOTA Net через **Настройки → Устройства и службы**.

Если интеграция уже установлена вручную, добавьте репозиторий и скачайте её через HACS поверх существующей папки. Удалять запись интеграции не нужно: логин, выбранные котлы, параметры и идентификаторы сенсоров сохраняются.

Последующие версии публикуются как GitHub Releases. HACS обнаруживает новые релизы; установите предложенное обновление и перезапустите HA. Репозиторий добавляется как пользовательский; в стандартный каталог HACS он пока не включён.

Версия 0.1.0 — первый публичный релиз с поведением rc4. Прежние ограничения проверки на реальном установленном HA сохраняются.

## Для сопровождающего

Для нового релиза измените `version` в `custom_components/zota_net/manifest.json`, выполните тесты и опубликуйте GitHub Release с тегом `v<version>` на нужном коммите. У каждого релиза должна быть новая версия; одного изменения файлов в main недостаточно для обновления пользователей, установивших релиз через HACS.

## Адрес API и авторизация

Адрес приложения по умолчанию: `http://control.zota.ru:81`.

**HTTP передаёт пароль и токен без TLS.** В форме настройки необходимо явно включить «Разрешить HTTP без шифрования». Без этого согласия вход по HTTP не выполняется. Если у вас есть подтверждённый HTTPS-адрес того же API, его можно указать вместо HTTP. Проверка сертификатов HTTPS всегда включена. Интеграция не следует HTTP-редиректам и не переключается самостоятельно на незащищённый транспорт.

Логин и пароль сохраняются в config entry Home Assistant, как данные обычной интеграции с password grant. Токен хранится в памяти и получается заново перед истечением срока; при HTTP401 выполняется одна повторная авторизация. Если она не удалась, HA предлагает повторный ввод пароля. Токены, пароли, сырые ответы API и серийные номера не выводятся в журналы этой интеграцией.

Поддерживается локальный логин/пароль ZOTA. Социальная авторизация без локального пароля в этой версии не реализована.

## Сенсоры

Каждый выбранный котёл становится отдельным устройством.

| Сенсор | Источник / единица |
|---|---|
| Мощность | Текущий API, кВт |
| Ступень мощности | Текущий API |
| Температура теплоносителя | Текущий API, °C |
| Температура помещения | Текущий API, °C; исправление наблюдаемого масштаба Solid X |
| Температура ГВС | Текущий API, °C; unknown при ошибке датчика |
| Статус | Текст API, например «Работа» |
| Количество ошибок / предупреждений | Размер списков Errors / Warnings |
| Давление (история) | Последняя точка истории, бар |
| Температура радиатора / улицы (история) | Последняя точка истории, °C |
| Последняя запись истории | UTC timestamp; HA отображает в своём часовом поясе |
| Ошибки / предупреждения | Бинарные диагностические сенсоры |
| История актуальна | Бинарный сенсор свежести последней записи |

В проверенном ответе `Air="217°C"` соответствует 21,7 °C. Для Solid X значения помещения по модулю больше 100 интерпретируются как десятые доли; уже дробное 21,7 °C и обычные значения градусного диапазона не делятся повторно. Правило основано на конкретном наблюдаемом серверном форматировании. Для другого формата/прошивки нужна проверка реальных данных.

`TempRoom` истории делится на 10; `Pressure` на 1000. Температурные коды ≥16384 и сообщения ошибки датчика дают unknown, не 0 °C. Это исключает ложные скачки температуры в статистике.

## Частота и свежесть

По умолчанию current опрашивается раз в 60 секунд, история — раз в 300 секунд. Интервалы и порог устаревания доступны в настройках интеграции. История запрашивается за последний час с offset=1; общий токен используется для всех выбранных котлов, запросы последовательные.

Давление и дополнительные температуры **относятся к исторической точке**, не к моменту опроса. Они имеют атрибуты `source=history` и `source_timestamp`. После 15 минут без новой записи числовые исторические сенсоры становятся unavailable. Дата последней точки остаётся видимой; «История актуальна» выключается. Кеш сохраняется при временной ошибке истории до истечения порога свежести.

У текущего API в проверенной модели нет времени обновления котла. Поэтому успешный ответ облака нельзя считать доказательством online котла; отдельного сенсора online в этой версии нет. Историческая свежесть позволяет отдельно видеть состояние поступления данных. Сбой чтения одного котла не отключает другие успешно опрошенные котлы.

## Статистика и ограничения

Температуры, мощность и давление имеют state_class=measurement: HA накапливает историю и долговременную статистику с момента установки при обычной конфигурации Recorder. Прежняя история ZOTA не импортируется в Recorder этой версией.

Отсутствуют управление котлом, уставки, насосы, Energy-счётчик и поддержка остальных моделей. Во время диагностики суточный запрос с offset=15 вернул лишь семь точек за 35 минут; полнота архивной истории не установлена. Наличие истории начиная с 29 июля 2026 подтверждено отдельным запросом первой точки.

Если ГВС/уличный датчик не установлен, соответствующий сенсор останется unknown. Нули вместо ошибочного датчика не подставляются.

## Проверка и диагностика

Сначала проверьте текущие показания и дату последней точки в HA, затем сравните их с ZOTA Net. При ошибках откройте Настройки → Система → Журналы, поиск `zota_net`.

```yaml
logger:
  default: info
  logs:
    custom_components.zota_net: debug
```

Публичные описания аварий API в этой версии не декодируются; показываются наличие и количество. Не публикуйте содержимое `.storage/core.config_entries`: там сохраняются данные входа.

Тесты API и преобразований (нужен aiohttp):

```bash
python3 -m unittest discover -s tests -v
```

Тесты Home Assistant используют установленный пакет HA; при его отсутствии пропускаются. Для разработки удобнее отдельное Python-окружение. В tests/solid_x_sample.json включены только очищенные показания и история, без аккаунта и идентификаторов котла.
